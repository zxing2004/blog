## 那些本该三秒完成的操作

同事发来一个几百行的 CSV，要你"把第三列大于 100 的行挑出来"；服务器上有一份几 GB 的日志，想统计访问量最高的十个 IP；一批文件名要统一去掉日期前缀。这些任务用图形界面做，要么打开表格软件慢慢筛，要么用编辑器一个个改——半小时起步，还容易漏。

如果你会一点 awk 和 sed，这些活儿往往就是一行命令、几秒钟的事。它们是 Unix 命令行里最经典的两个文本处理工具，几十年来几乎没有变过，至今仍是处理结构化文本和日志的瑞士军刀。更妙的是它们天然支持管道，可以像乐高一样把简单命令拼成复杂流水线。

很多人对 awk/sed 望而生畏，是因为觉得语法像天书。其实只要掌握几个核心模式，就能覆盖日常九成需求。本文不讲完整语法手册，只讲最能立即上手的实战技巧。

## awk：按字段处理与条件过滤

awk 把每一行按分隔符切成若干字段，`$1` 是第一个字段，`$2` 是第二个，`$0` 是整行。默认分隔符是空白（空格或制表符），可用 `-F` 指定：

```bash
# 打印 /etc/passwd 的用户名（第一列，冒号分隔）
awk -F: '{print $1}' /etc/passwd

# 挑出第三个字段大于 100 的行
awk '$3 > 100 {print $0}' data.txt

# 对第二列求和，END 块在处理完所有行后执行一次
awk '{sum += $2} END {print "总计:", sum}' sales.txt

# 输出带格式的表头与字段
awk -F, 'BEGIN{print "名称\t金额"} {printf "%s\t%.2f\n", $1, $2}' data.csv
```

awk 的语法核心是"模式 {动作}"：对每一行，若模式为真就执行动作。`BEGIN` 和 `END` 是两个特殊模式，分别在处理前和处理后执行，常用来初始化变量和输出汇总。掌握了这三点，你已经能写大部分 awk 脚本了。

## sed：流式编辑与替换

sed 是流编辑器，最常用的是替换命令 `s/旧/新/标志`：

```bash
# 把每行所有的 foo 替换成 bar（g 表示全局）
sed 's/foo/bar/g' file.txt

# 只替换每行第一次出现的 foo
sed 's/foo/bar/' file.txt

# 打印第 2 到 5 行（sed 默认会打印所有行，-n 关闭后按需打印）
sed -n '2,5p' file.txt

# 删除含 DEBUG 的行，并原写回文件（-i）
sed -i '/DEBUG/d' app.log

# 在含 TODO 的行前插入说明
sed '/TODO/i\  # 待处理' file.txt
```

替换中的分隔符不一定是斜杠，当内容含斜杠（如路径）时可换成其他字符：`sed 's#/old/path#/new/path#g'`。正则在 sed 和 awk 里都可用，`.` 匹配任意字符，`.*` 匹配任意长度，`^` 和 `$` 匹配行首行尾，`[0-9]` 匹配数字——掌握这几个就够应对多数场景。

## 十个高频 one-liner

下面十条是我在日常里反复使用的命令，覆盖过滤、统计、替换、批量操作等典型场景：

```bash
# 1. 打印文件的第一列
awk '{print $1}' file.txt

# 2. 按冒号分隔并打印第 1、3 列
awk -F: '{print $1, $3}' /etc/passwd

# 3. 条件过滤：第 3 列大于 100
awk '$3 > 100' data.txt

# 4. 求和：第 2 列总和
awk '{s += $2} END {print s}' data.txt

# 5. 统计每行出现的次数（按出现次数倒序）
sort file.txt | uniq -c | sort -rn

# 6. 全局替换并输出到新文件
sed 's/foo/bar/g' a.txt > b.txt

# 7. 删除空行
sed '/^$/d' file.txt

# 8. 显示第 10 到 20 行
sed -n '10,20p' file.txt

# 9. 找出日志里访问量最高的 10 个 IP
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10

# 10. 批量把所有 .txt 文件改成 .md 后缀
for f in *.txt; do mv "$f" "${f%.txt}.md"; done
```

这十条的价值在于**组合**：第 9 条就是 awk（取字段）+ sort（排序）+ uniq（去重计数）+ sort（再排序）+ head（取前十）的流水线，每一步只做一件事，串起来却完成了复杂的统计分析。这种"小工具 + 管道"的思维方式，比记住某个大而全的工具更重要。

## 实战：批量改名与日志分析

**批量改名**看似简单，实则暗藏风险。上面第 10 条的 `${f%.txt}` 是 Shell 的参数展开，表示去掉 `.txt` 后缀。更稳妥的做法是先"预演"再执行，避免手滑改错：

```bash
# 第一步：预演，只打印将执行的命令，不实际改动
for f in report-*.txt; do
  echo "mv '$f' -> '${f#report-}'"
done

# 第二步：确认无误后去掉 echo 真正执行
for f in report-*.txt; do
  mv -- "$f" "${f#report-}"
done
```

`${f#report-}` 表示去掉开头的 `report-` 前缀。用 `--` 结尾防止文件名以短横线开头被误认为参数。这种"先 dry-run 再执行"的习惯，是批量操作的安全带。

**日志分析**是 awk 的主场。假设要统计每个接口的平均响应时间（URL 位于第 7 个字段，耗时位于最后一个字段），可以这样写：

```bash
# 统计每个 URL 的请求数与平均耗时
awk '{url=$7; total[url]+=$NF; cnt[url]++} \
     END {for (u in cnt) printf "%6d 次  平均 %.3fs  %s\n", cnt[u], total[u]/cnt[u], u}' \
     access.log | sort -rn | head -20
```

awk 用数组 `total[]` 和 `cnt[]` 按 URL 累加，最后在 `END` 块里计算平均值并格式化输出。这种"分组聚合"的模式，本质上就是 SQL 里的 `GROUP BY`，awk 用几行就能实现。

## 最佳实践与踩坑

第一，**先用小样本验证命令**，再对大文件执行，尤其是带 `-i` 原地修改的操作，`sed -i` 是不可逆的。第二，**注意不同系统的 sed 差异**，macOS 自带的 BSD sed 与 Linux 的 GNU sed 在 `-i` 参数上语法不同（BSD 需要 `-i ''`），跨平台脚本要留意。第三，**文件名含空格时必须加引号**，`"${f%.txt}"` 的引号不能省，否则会被拆成多个参数。第四，**正则里的特殊字符要转义**，点号、星号、方括号在正则中有特殊含义，匹配字面量时要加反斜杠。第五，**复杂逻辑写成脚本文件**，用 `awk -f script.awk` 调用，比在命令行里堆一长串更易维护。第六，**大文件处理用流式工具而非一次性读入内存**，awk/sed 天生逐行处理，这点比写脚本读全文更省资源。第七，**善用 `BEGIN` 与 `END` 做汇总输出**，让程序在处理完所有行之后统一打印结果，而不是边读边输出，这样表格更整齐，逻辑也更清晰。

## 小结

awk 擅长按字段拆解与聚合，sed 擅长流式替换与过滤，而管道把它们串成了无限可能的流水线。掌握"模式—动作"的 awk 心智模型和 `s/旧/新/` 的 sed 替换语法，你就能把大量重复的文本操作压缩成一行命令。建议从本文的十条 one-liner 开始，每条都亲手跑一遍、改造一次，逐渐你就会形成自己的命令片段库。下次再遇到"把某一列挑出来"这类需求时，你会庆幸自己学会了这些老而弥坚的工具。
